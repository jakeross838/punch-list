# Setup

How each service behind the app is set up, and where its secrets are kept. Secrets are kept only in `local/secrets/` in the build workspace, which git ignores; none are in the code. Everything here was set up on 4 November 2026.

## Supabase

- Project `punch-list` (`ulwewwyhestgxpxdiwme`), organization ross-built-platform, Canada Central.
- The database is the migrations in `supabase/migrations`, applied in order (see The live database in `phase-1.md`).
- Sign in is by email with a six digit code: the Magic Link and Confirm Sign Up templates carry the code (`{{ .Token }}`), subject "Your Ross Built sign in code" (to change to "Your Punch List sign in code" now that any company signs up), and the code length is 6.
- Anyone signs up (6 November, `many_companies` migration): after the code, someone new names their company and becomes its admin (`public.start_company`), then adds their people under People; someone an admin added goes straight in. `public.my_account` says where a signed-in email stands. Delete My Account (`public.delete_my_account`) takes the sign in away and the person's name, email and phone off their records; the last person at a company takes the whole company with it, photos included.
- The Before User Created hook still runs `public.hook_only_ross_built_people` (the name the Auth settings point at). It now lets anyone sign up, and turns away only someone switched off at their company: "That email is switched off at Ross Built. Ask an admin there to switch it back on."
- Email: Supabase's own sender only sends to the organization's team. jake@rossbuilt.com is invited to the team as a Developer, and with the invitation still open his codes already arrive (checked 5 November: a code reached his inbox in about a minute and a half). Keep the invitation; it may be what lets them through. Before anyone else signs in, the email needs its own sender (custom SMTP, for example Resend with a verified domain), set in Authentication, Emails, SMTP Settings.
- Checked end to end on 5 November: a code emailed to jake@rossbuilt.com signed him in, PowerSync accepted that sign in and finished the first sync (the `mine` and `ross_built` streams; only his own People row so far, since no jobs are loaded), and the test session was signed out.
- PowerSync's database role, `powersync_role`: can log in and replicate, reads past the access rules (PowerSync's sync config is the gate for the phones), and can only read the tables in `public`, which are exactly the tables in the `powersync` publication. It was made by hand, not in a migration. Its password was made in the build workspace and only its SCRAM hash was sent to the database. The password is `POWERSYNC_DATABASE_PASSWORD` in `local/secrets/powersync.env`.

## The company's page (6 November 2026)

- The page: `apps/company-page`, one small web page (about 33 KB, the script inside it), built by `node tools/build-company-page.mjs` into `apps/company-page/dist`. It is on Expo's hosting for the Punch List project: `https://punch-list.expo.app`, with each link at `https://punch-list.expo.app/c#<token>`. The token goes after the #, so the hosting never sees it. `https://punch-list.expo.app/c#sample` is the sample page, answered in the browser and sent nowhere; the preview's links all go there.
- To put a new version up, from `apps/mobile` with the Expo token from `local/secrets/expo.env` in the environment:

  ```
  node tools/build-company-page.mjs
  cd apps/mobile && npx eas-cli@latest deploy --export-dir ../company-page/dist --non-interactive --prod
  ```

- The function: `supabase/functions/company-page`, deployed with verify_jwt off (the link is the only key). Every call is a POST with the token in its body; it checks the link, answers through the `trade_*` database functions as the service role (nobody else can call them), and signs the photos for an hour. Supabase does not serve web pages from functions, which is why the page itself is on Expo's hosting.
- The job's station is built into the same place by the same command: `https://punch-list.expo.app/s#<token>` on a tablet and `https://punch-list.expo.app/tv#<token>` on a TV, with `#sample` for the sample. Its calls go to the same function with the station's token as `s`: alone for the board (`station_page`), or with a company for that company's list, opened through the company's own link (`station_company` finds it, or makes it), which never leaves the function. The app gets, makes and turns off the station's link through `job_station`, so it needs a signal. `npx tsx tools/station-e2e.ts` walks it against a stand-in, after `COMPANY_PAGE_FUNCTION=http://localhost:4321/fn node tools/build-company-page.mjs`.
- Later: the page can move to the company's own address (for example `link.rossbuilt.com`, or one for Punch List) by pointing a domain at Expo's hosting and setting `EXPO_PUBLIC_COMPANY_PAGE_URL` in the app's build.

## Reading the plans (7 November 2026)

- The function: `supabase/functions/read-plans`, live since 7 November (version 2 since build 13, with the allowance; version 3 since build 14, with Read a List), deployed with verify_jwt on (the caller signs in). The phone puts the plans in the job's folder in the photos bucket (`<job>/plans/read-<id>.pdf`, or each picture whole and in pieces as `read-<id>-<sheet>-<piece>.jpg`) and calls it with where they are. It checks the caller is switched on at a company with some of this month's allowance for Claude left and can see the job, signs each file for ten minutes, gives Claude the links (a PDF as a document, pictures as images), and answers with Claude's reply. While Claude reads it sends a space every ten seconds, so the phone's connection stays open. Once Claude has answered it takes the files out of storage, as the service role, and counts what the reading cost against the company.
- `{ check: true }` answers whether the Claude key is set. The app shows Read the Plans only once it says yes, and asks again every five minutes, so setting the key needs no new build.
- `PLANS_MODEL` can name another model; it is Sonnet otherwise. To deploy: `supabase functions deploy read-plans` (or through the Supabase connector), with `index.ts`, `core.js` and `claude.ts`.
- Version 4 (live since 8 November, once Jake said to) also asks Claude which page or picture shows each level's floor plan (`sheet`), so the app keeps that sheet as the level's plan in Plans. The phone keeps it from pictures of the sheets; a page of a PDF is kept on the preview, where the page is drawn with the PDF reader, and on the iPhone a screenshot of it goes in with Add a Plan.
- Limits: a PDF up to 30 MB (Claude reads up to 32 MB and 100 pages at once), up to six pictures. On Supabase's free plan a function can run for 150 seconds, which is room for a set of plans; a very big set may need the floor plan pages sent on their own.

## Claude in the app (7 November 2026)

- The function: `supabase/functions/ai`, live since 7 November (version 1; version 2 since build 14, with Round 2's tasks), deployed with verify_jwt on. Every other use of Claude on the iPhone goes through it: Fill In From Photo, Say It, the same work written twice (as an item is written, and Find Duplicates), and standard wording. The phone names one of the tasks in `packages/core/src/claude.ts` and sends its input, with a photo or a few when the task takes them; the function builds the words from the core, so nothing else can be asked on the key. Quick questions go to Haiku, photos and Say It to Sonnet (`QUICK_MODEL` and `SHARP_MODEL` can name others).
- Both functions need the Claude key as a function secret: in the Supabase dashboard, Edge Functions, Secrets, add `ANTHROPIC_API_KEY` (from console.anthropic.com, API Keys). Until it is there the app hides Claude's buttons, and it asks again every five minutes, so adding the key needs no new build.
- What each answer cost is counted in `ai_usage`, by the functions as the service role, at each model's price (Sonnet 5.5: 2 dollars a million tokens in, 10 out; Haiku 5.5: 10 cents in, 50 out). Each company has a monthly allowance: 25 dollars unless `ai_limits` says otherwise (Ross Built's is 200 dollars). Once it is used, the functions ask nothing more until the first of the month, and the app says so. An admin sees this month's cost on the Me screen, under Claude. To change a company's allowance, as the app's owner: `insert into ai_limits (org, monthly_cents) values ('<company id>', 5000) on conflict (org) do update set monthly_cents = excluded.monthly_cents;`
- The words, the tasks and the prices come from `packages/core`, so the iPhone, the preview and the functions ask the same way, and the two functions share `supabase/functions/_shared/claude.ts`. `npm run build:functions` writes `core.js` and `claude.ts` into each function's folder (a function cannot reach other folders once it is deployed), and a unit test fails when they are behind.
- `DENO=/path/to/deno npm run test:functions` runs both functions on this computer against stand-ins for Supabase and Claude: who they turn away, the tasks and photos they take, the model each task goes to, the allowance, the counting, the open connection while Claude works, and for read-plans the links Claude gets and the files taken away.
- Say It writes down what is said on the iPhone itself with Apple's speech recognition (`expo-speech-recognition`, on the phone when the phone can), so it needs a new build and asks for the microphone and speech recognition the first time. The preview link has no microphone: the words are typed there.
- Round 2 asks Claude four more things through `ai`: the done check (the photo of the problem and the done photo, on Sonnet), a company from a business card or an email signature (Sonnet), what a new item waits on, and which column is which in a spreadsheet (both Haiku). Read a List sends a punch list's PDF or pages through `read-plans` with `kind: list` and the job's names as `input`; it is counted as `read-list`.
- A company's done photo comes to `company-page` as `action: photo`, a JPEG in base64 made smaller on the phone (the one call allowed past 8,000 characters, up to 3,000,000). The function asks `trade_photo_folder` for the item's folder, puts the photo at `<job>/<item>/done-<uuid>.jpg` as the service role, then `trade_add_photo` puts it on the item (at most ten done photos on an item); if that refuses, the file is taken away again. Live since 7 November: the migration `done_photos` (live as 20261108031902), `company-page` version 3, and the companies' pages and the station published again.
- Merging two items is the database function `merge_items`: the one kept takes the other's photos and comments, what waited on the other waits on it, and the other is removed, with a line in Activity. On the phone it needs a signal and every change made on the phone up first. Not the Same in Find Duplicates is kept on each phone.

## PowerSync

- Organization jakeross838, project Punch List, instance Production (United States): `https://6aeb7afcb0047aeb6df99617.powersync.journeyapps.com`.
- `powersync/service.yaml` is the instance: the database's direct connection as `powersync_role`, and sign in with Supabase Auth (`supabase: true`; PowerSync reads the project's signing keys itself). `powersync/sync-config.yaml` is what each phone receives. `powersync/cli.yaml` links the folder to the instance.
- The PowerSync access token is `PS_ADMIN_TOKEN` in `local/secrets/powersync.env`.
- To change the instance or the sync config, edit the files, then deploy with the PowerSync command line (version 0.10.3; on Node 22 it needs the flag shown):

  ```
  mkdir -p /tmp/pscli && (cd /tmp/pscli && npm install powersync@0.10.3)
  set -a && . local/secrets/powersync.env && set +a
  node --js-explicit-resource-management /tmp/pscli/node_modules/powersync/bin/run.js deploy
  node --js-explicit-resource-management /tmp/pscli/node_modules/powersync/bin/run.js status
  ```

- Checked: the connection test, the sync config check and the deploy pass; the first copy of the database is done and every synced table replicates; a request with no sign in is refused.
- Deployed again on 5 November for build 4, with the plans (`plan_sheets`) and the items' new columns: run from the repository root, since the command line looks for the `powersync` folder there. Supabase changes go in first, then the sync config, then the build, so a phone never asks for a table the database does not have yet.
